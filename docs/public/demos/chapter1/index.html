模型公式与实测对照

GEMM：F=2×596M×B，Bytes=2×596M（本原型忽略激活流量）；KV：F=4×B×ctx×2048×28，Bytes=4×B×ctx×1024×28。各组件分别取 max(F/Peak, Bytes/BW)，再相加；Peak=195 TFLOP/s，BW=640 GB/s。聚合吞吐=1000B/t_ms，每请求吞吐=1000/t_ms。

课件已有实测（ctx=1024，eager）：B=1 / 4 / 16 的 wall time 分别为 29.30 / 29.43 / 29.58 ms。这些是独立测量锚点，不作为本图解析曲线；差异见实验 03。

GPU 为什么会等 CPU？

当发射速度跟不上执行速度，GPU 会在相邻 kernel 之间等待。

这个动画能说明什么？

第 i 个 GPU kernel 的开始时刻 = max(CPU 发射完成时刻, 上一个 GPU kernel 的结束时刻)。缩短发射间隔可以减少等待，但该示意不提供 CUDA Graphs / compile 的实测加速比。40 个等时 kernel 不能精确复现课件 profiler 的 1591 个异构 kernel。
